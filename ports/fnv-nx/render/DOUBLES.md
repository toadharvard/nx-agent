# Test doubles census (render and tests/l6)

Base commit 24f18cdb (claude/fnv-l6-render-w2) on claude/fnv-l6-render-w5; the commit that carries this file is the census commit (see the report).

Rule (CLAUDE.md, no doubles in tests): per test binary, (symbols the test defines) ∩ (symbols the product roots define) = ∅. Boundary (GL library, deko3d, libnx, kernel) does not count.

## Method (mechanical, no allow-list)

- Product set: `nm -g --defined-only` (aarch64-linux-gnu-nm) of the 69 objects of render/d3d9 built by `recipe.py build --root ports/fnv-nx/render/d3d9` (green, 1420 defined global symbols; `dev/ffp_prog.cpp` is not in it, see MARKERS.md). It is the only admitted root with a recipe. Host-compiled `nm` of render/backend/nx/dk_*.c, nxgpu4_check.c, render/gl4/gl4_*.c and render/shaders/src/* is a second set (no admitted root yet): 0 collisions.
- Test side: per test driver, its own sources = every .c/.cpp/.cc under the test's directory plus every source basename the driver .py names that exists outside the product dirs. Compiled with host g++/gcc `-c -m32` (64-bit retry for libnx headers), `nm -g --defined-only`; weak symbols and `main` excluded. Run-time generated headers produced with the generators the tests call: gen_bridge.py, gen_wrap.py, envq.emit/emit_fmt, rows.gen.h (test_bridge's own code), d9impl/state/env_table (the recipe's generated steps, taken from the store).
- Match: mangled name, or demangled name without parameter list (ILP32 aarch64 vs host -m32 mangling differ). A file shared by several tests counts once per test (summed) and once as a file.
- Host compile for `nm` only; this is a census, not a build.

## Totals (all 40 test drivers, census at this commit)

- Tests: **40**: fully measured 24, partly measured 5, none measured 2, no C/C++ source of their own 9 (python-only drivers or Wine/mingw run-time builds).
- Against render/d3d9: tests with a collision **17**, doubling files **14**, distinct symbols **30**, summed over tests **173**.
- Against the second set (backend/GL4/shaders): 0.
- Previous run of this census (before the run-time headers): 17 tests, 14 files, 30 distinct, 173 summed. Now: see above.

## Plan to 0

The class of each symbol: all 30 colliding symbols are (a) (a real unit of render/d3d9 defines them: table above). Linking the real unit changes the test's link closure, which is the 69 objects of the root. What the closure leaves undefined, measured from `objects.json` of the root (80 names): libc (mem*, str*, malloc/free, cos/sin/pow/exp/sqrt), the C++ runtime (`operator delete`, `__cxa_*`, `__aarch64_ldadd4_relax`), `fnvnx_dispatch`, `fnvnx_guest_invoke`, `fnvnx_import_key`, `fnvnx_wine_fixme`, the vtables of the interfaces (the guest's, resolved by the exe), and the boundary functions:
- `nxd3d_gpu_call`, `nxd3d_gpu_alloc`, `nxd3d_gpu_free`, `nxd3d_dc_create`, `nxd3d_dc_release` — the nxgpu ABI: class (b), served by the real GL backend (render/gl4, L6A) behind L4's shared model; today only RPC doubles in the tests (t_rpc.cpp, server.c) provide them, and they define no symbol of the root, so they are boundary, not doubles.
- `nxd3d_perf_counter`, `nxd3d_os_cursor_pos`, `nxd3d_window_client`, `nx_env_profile` — platform/kernel hooks: L4 shared model / L5.
- `nx_ffp_ps_program`, `nx_ffp_vs_program` — defined by `dev/ffp_prog.cpp`, which is not buildable yet (ffp_glsl.gen.h and the ffp_dksh.gen.h have no recipe step, needs the uam binary): blocks every test that links the closure. Owner: L1 (host-tool stage) / L6 lead.
Consequence: every one of the 17 tests (all class a) reaches the nxgpu boundary through the real unit. Dropping the test's own definition is a one-line change, but the test can only link and run when (1) ffp_prog.cpp builds in the root, (2) the test is rebuilt by recipe.py as a product root test target (the old build_guest.sh is gone) and (3) the boundary above is provided by L4's shared model. Per test the real definitions to link are those named in the table; for t_env.cpp-style tests (devlife, m1, pvw, res, tex, present, const) that is glue_buf/glue_image/glue_present/glue_query.cpp and d3d9_adapter.cpp, for t_factory.cpp (dev) res_surf/res_fvf/glue_image, for t_exports.cpp d3d9_adapter/x1_validator, for t_oom.cpp obj.cpp, for t_x1.cpp app_unk_guest.cpp and d9bridge.gen.cpp, for tests/l6/native/app_unk_native.cpp (bridge, x1) app_unk_guest.cpp.
- Class (c) (failure injection): t_oom.cpp injects allocation failure by redefining nxd3d_alloc/nxd3d_free (obj.cpp). The real obj.cpp calls malloc/free: the injection must become an input of L4's shared allocator model.
- Class (b): none of the 30 symbols is below the nxgpu ABI; (b) is the boundary list above.
