## Classes
| class | meaning | oracle.json REF kind that fits |
|---|---|---|
| W-rec | expected values recorded from a Wine 9.0 run (env_*.tsv, D9S1 streams, Wine conformance runs) | `wine-exe` (needs an artifact in fnv-nx-build) |
| W-src | expected values written from cited Wine 9.0 source (function or file named) | `spec` (needs cited text in a tracked file outside product roots) |
| MS | expected values from an MS document: a D3D9 doc page, asm reference, SDK header | `spec` |
| SPEC | expected values from `render/d3d9/spec/d3d9_spec.json` | `spec` (but the file is inside the product root `render/d3d9`) |
| MODEL | independent model written in the test (python/C CPU reference, hand count, hash function); no external document | `model` |
| NONE | no reference: values come from the product's own code, its own generator/translator, a previous run, or there are no values (property, mutation or gate test). A red to fix. | none |
Primary class = the strongest external source the test uses today (order W-rec, W-src, MS, SPEC, MODEL, NONE). "Also" lists secondary sources.

## What the oracle gate would say today (read from `verify/gate_oracle.py`, not run)

1. **Universe.** The gate certifies the `DIR/tests/test_*.py` of the DIRs in the `selftests` argv of `verify/gates.json`. `tests/l6/**` is not an admitted root, `render/d3d9`'s gate list has no `selftests`, and `render/total` is not admitted. So no render test is in the universe: the 42 are uncertified because they are not seen. L1 owns the form (class `test` root, as in DOUBLES.md).
2. **Rule 5 (product subject needs `wine-exe` or `spec`, and no REF path in a product root).** The only reference files the render tests use today are `render/d3d9/spec/d3d9_spec.json`, `render/d3d9/env/env_*.tsv` and `ENV_PIN.txt`, all inside the product root `render/d3d9`: illegal REF paths. Tests whose reference is an independent model (MODEL) fail rule 5 by themselves: they have no `wine-exe` and no `spec`.
3. **No tracked file outside the product roots holds Wine 9.0 or MS text.** `docs/RENDER.md` and `docs/RENDER_VERIFY.md` hold none (checked their headings). So W-src (9 primary, 18 in all) and MS (8 primary, 12 in all; 23 tests use one or both) have no legal `spec` REF.
4. **`wine-exe` does not fit the Wine recordings.** The kind means a dump the game's exe produced under Wine (`exe_sha256` = `oracle_pins.json`). `env_*.tsv` is recorded from `envprobe2.exe` (ENV_PIN.txt: sha256 6f64a3af...), a probe, not the game's exe, and the artifact is not in fnv-nx-build.
5. Class NONE (10 tests) has no record by definition.

Asks to L1 (the form), in one rule: (a) a REF kind for Wine 9.0 source = {wine 9.0, file, function, sha256 of the pinned source tarball as an external} and one for the MS SDK/doc page, both read-only citations outside the product roots; (b) a REF kind for a Wine-recorded probe dump (probe exe sha256 + artifact commit + tree_sha256) beside `wine-exe`; (c) admit `tests/l6` (or its successor) as a `test` root. Until then the W-src, MS, W-rec rows stay "reference named in the docstring, not certifiable".
