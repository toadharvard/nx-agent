# l2-source-002 — имена MSVC из деревьев GCC, модель данных exe в компиляторе, разбор 27 падений (2026-11-10)

Ветка `claude/fnv-l2-source`, голова 39b22cde. Оракул во всех пунктах — настоящий cl (MSVC 2008 SP1 под Wine, поднят
в контейнере через `tools/equiv/setup_msvc.sh`).

## Сделано

- **DISPATCH1 по интерфейсу L3.** Место вызова — одно 64-битное слово (ключ | вход << 32, одна загрузка);
  `fnvnx_dispatch(адрес exe, место, описатель)`; описатель `conv:ret:args` из типа вызова GCC. 13 из 13 и 65 из 65
  юнитов, ошибок плагинов 0.
- **CC1.** `__cdecl/__stdcall/__fastcall/__thiscall` не стираются, а становятся атрибутом типа `fnvnx_cc` (под
  `FNVNX_SDD`). Факт из `units.json`: ни у одного из 2 988 юнитов нет `/Gr` или `/Gz`, умолчание не-члена — cdecl.
- **FTOI, enum.** cl отвергает `(E)f` ошибкой C2440 для любого enum. Плагин больше не выбирает путь int: прямое
  float → enum — ошибка компиляции. На 65 юнитах таких мест 0.
- **27 падений `FNVNX_SDD=1` на фермах** (головы c7ced27 / a429e4f), по классам:
  - 17 юнитов — дефект плагина N3: копия функции искалась по первой точке в имени символа, а у функции статической
    инициализации в имени стоит имя файла. Теперь по происхождению объявления.
  - 5 юнитов — классы Havok с одними placement-формами `operator delete[]`. По cl: `??_E` освобождает массив обычным
    членом `delete[]` (`(void*)` или `(void*, size_t)` с `sizeof(класса)`), иначе глобальным `operator delete(void*)`
    (`??3`). Слот-функция SDD2 делает то же; умолчание исправлено с `::delete[]` на `::delete`.
  - 2 юнита — дефект SDD2: символ точки адреса принимался за таблицу.
  - 4 юнита — дерево было подготовлено с пятью эвристическими правилами; на дереве с `FNVNX_PREPARE_SKIP` собираются.
  - Локально на исправленной голове: 27 из 27.
- **NAMES1** (`toolchain/names`): имя MSVC каждого внешнего символа объекта из деревьев GCC (`.fnvnx.sympair`) и имя
  vftable каждой точки адреса по правилу путей MSVC (`.fnvnx.vtpair`). `test_names.expect` — таблица символов cl для
  `test_names.cpp`: 282 имени совпадают, 9 заявленных дыр.
- **Гейт `tools/link/namegate.py`** на объектах cl того же подготовленного дерева: 36 юнитов (остальные 29 из 65 cl не
  собирает из-за GCC-измов платформенных правил). Определения: 736 из 739 равны cl (1 — `size_t`, 2 — исходник сам
  разный под компилятор); ещё 4 637 inline/ссылочных имён найдены в объекте cl того же юнита; безымянных строк 0.
  Эталон из исходного декомпа (`msvc/pristine`) для этого гейта не годится: prepare меняет объявления.
- **COOKIE1**: счётчик перед массивом `new[]` — всегда один `size_t` (хук `get_cookie_size`); cl для класса с
  выравниванием 8 читает `[this-4]` и освобождает `this-4`.
- **MSVCMODEL1** (`toolchain/msvcmodel`): патч GCC 13.3.0 для `-mabi=ilp32` — `size_t` = `unsigned int`, `ptrdiff_t` = `int`;
  счётчик массива ⇔ нетривиальный деструктор элемента; в размерный `delete[]` идёт `sizeof(элемента)`; переполнение
  размера `new[]` передаётся аллокатору как наибольший размер. Числа приёмочного теста сняты с cl. Патч накладывается
  на официальный архив (sha256 зашит); сборку делает L4, зеркало `tools/gcc-ilp32-msvcmodel`.
