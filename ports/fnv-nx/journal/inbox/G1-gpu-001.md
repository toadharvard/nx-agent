* **found**
  - The real-game capture binds pixel shaders from shaderpackage010/011, not 019. The VS hashes exist in 019; none
    of the 19 PS hashes do. The engine picks the package from the adapter caps (under Wine: WineD3D on llvmpipe).
    real019 may cost the wrong package for the Switch. Someone needs to decide which package our driver's caps
    select. A real010/011 scene is cheap to add.
  - D20 ambiguity: the exe default shadow-map resolution is 256. Fallout_default.ini (the launcher's file) sets
    1024. I followed "the exe's own defaults" literally. With 1024 the shadow term grows about 16x in pixels.
  - Translated ps < 3.0 still carry the runtime fog chain, 47 instructions in SLS2117. ISCOPY is still 76
    instructions for a copy. The model counts these static instructions as executed, so it over-states the
    executed cost by roughly the epilogue arms not taken.
  - real019's shader costs come from the D3D9 translator, but the shipped renderer draws with render-lit and
    render-land's native families. The translator cuts lower real019 and speed up the translated fallback and
    replay. The cuts that carry over to the shipped frame are pass structure, render-target formats and bandwidth.
