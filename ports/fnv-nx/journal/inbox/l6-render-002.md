- d9cap пишет эффекты, а не вызовы (UP-draw → несколько записей, Lock → запись при Unlock).
- README обещает счёт FVF-draw в `unjournaled`; код их не считает.
- `d3d9_exec`: исполняет 44 метода, 446 отсутствуют. Null-устройство: 164 метода с состоянием, 330 возвращают константу.

Вывод: точная сверка потока на d9cap невозможна. Решение — RD1 (заметка 001), принято оркестратором.

## Решения оркестратора 2026-11-10

- d3dx9_38.dll идёт в MODULE-LIFT (L3 лифтит, L5 грузит); граница ровно на d3d9.dll.
- Доказательство «байткод Create*Shader только из shaderpackage» ведёт L1; при неудаче транслятор идёт в рантайм с кэшем по хэшу.
- Вместо null-устройства — тот же фронт на GL 4.5/llvmpipe (RD8).
