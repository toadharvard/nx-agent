## J-XXXX L1 CONTRACT: загрузчик и старт — правила швов и оценка стоимости (чтение кода, без правок)

Статус: предложение, ждёт решения оркестратора. Замеров новых нет; оценки посчитаны из размеров ELF e1ca6b02 и exe.

### Что сейчас стоит инструкций (docs/PERF.md, счётчик L4: 357 М до WinMain)
Основное — не перемещение и не обнуление, а работа, которая является функцией (байты exe, addrmap) и повторяется на каждом запуске:
поиск указателей кода сканированием образа с «уверенностью» (`fnvnx_scan_codeptrs` дважды, `fnvnx_image_ptr`, `fnvnx_codemap_find`),
разбор `.reloc`, сортировки, поиск таблицы `__xc`; затем байтовый `early_zero` по bss и три memset окна данных и образа гостя.

### Правила
- **S1 START = точка входа exe.** Загрузчик делает только то, что делает загрузчик PE: отображает секции, ставит защиту по
  заголовкам, пишет адреса кода и импортов, заводит TLS, передаёт управление гостевому входу `AddressOfEntryPoint`.
  `__xi`, `__xc`, разбор командной строки, `__argc/__argv`, WinMain, `doexit`/atexit исполняет CRT самого exe (его функции вне
  декомпиляции, значит LIFTED по BODYSEL). Порядок инициализации тогда равен exe по построению. Уходят: `capture_xc`, `xctab`,
  свой onexit, пропуск 8 записей `__xi`, stand-in конструктора MemoryManager, `winmain_cmdline`, режим ADDRESS.
- **S2 PTR = `.reloc`.** Множество слов образа с адресом кода — это релоцированные слова со значением в `.text` (exefacts:
  101 449). Оно точное по контракту PE; сканирования, классов уверенности и проверки «слово ещё держит цель» нет. Линк выпускает
  готовую таблицу пар (адрес образа, нативный вход); у каждого адреса кода есть гостевой вход (R5), trap-заглушек нет.
- **S3 ZERO = страницы ОС.** Память окна данных и образа гостя берётся свежими страницами, которые ядро отдаёт нулевыми; циклов
  обнуления нет. Допущение A-ZERO: Horizon обнуляет выдаваемые страницы (svcSetHeapSize / отображение); повторное использование
  страниц внутри процесса запрещено правилом загрузчика.
- **S4 IMG-ID.** Таблицы S2 верны только для того exe, из которого построены: загрузчик сверяет SHA-256 файла с закреплённым
  значением до отображения. Это инвариант входа, а не эвристика.
- **S5 TLS по контракту PE.** Индекс модуля exe = 0, блок потока = копия шаблона каталога TLS (0x2c4 байта) для каждого потока при
  создании, `fs:[2Ch][0]` указывает на него; нативные и lifted-тела читают один и тот же блок (SECREL-релокации в N1).
- **S6 PROT.** Защита секций по заголовкам PE (`.text` и `.rdata` только чтение) — этого требует и R3/A6.
- **S7 Перемещение гостя** остаётся (D9), но только RELR/RELATIVE; 200 PC-относительных релокаций, верных лишь у базы линка
  (TOOLCHAIN.md «pinned»), — нарушение, гейт `pcrel_abs` = 0.

### Нарушения приказа в нынешнем пути старта (все уходят с S1-S6)
trap-заглушки для указателей без цели (4 096) и «вернуть 0»; trap-заполнение несвязанных слов IAT; пропуск записей `__xi`;
«not run» для инициализаторов без тела; stand-in MemoryManager; все секции RW; порядок ADDRESS как запасной путь; пустой образ
без exe; фиксированные `argc/argv`; классы уверенности при поиске указателей.

### Чего у правила нет
- Сверка S4 при каждом запуске стоит около 25 М команд; сделать её один раз «при установке» можно только с доказанной
  неизменностью файла, такого правила у меня нет.
- A-ZERO не проверяется без прогона на консоли.
- Таблица окружения и командной строки — ENV-TRUTH (L5, владелец).
