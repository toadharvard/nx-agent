## J-XXXX L2 SOURCE: SDD2, один слот деструктора внутри компилятора (2026-11-10)

- machine: l2-source, ветка `claude/fnv-l2-source`
- база: линк e1ca6b02d60d, дерево t/e1ca6b02d60d (hash b1d10daa389801f2), 65 юнитов (15 самых больших игровых + 50 случайных, seed 1)

### Решение

SDD1 (правка исходников макросами, `rules/sdd1.py`) снят: он ставил макросы по тексту и угадывал полиморфность по имени
базы, а его inline `__sdd` требовал определить неявный деструктор там, где оригинал его не определяет (2 юнита из 65
не собираются, в C++ это не лечится). Заменён на SDD2: плагин GCC `toolchain/sdd`, исходники не правятся.

Правило SDD2: GCC сам делает невиртуальным вариант D2 деструктора (cp/class.cc build_clone). Плагин делает то же с D0
в единственной точке, где это ещё возможно: finish_struct_1 зовёт target-хук key_method_may_be_inline для каждого
класса с vptr после клонирования деструкторов и до раздачи слотов. Дальше фронтенд сам строит всё с одним слотом:
BINFO_VIRTUALS, индексы, таблицы, thunk-и, VTT, construction vtables, указатели на виртуальные члены, свёртку.
Остаётся: (1) запись D1 в таблице → `<D1>.fnvnx_sdd(this, flags)` = `??_G`; (2) виртуальный вызов слота деструктора
получает flags 0, delete-выражение (теперь прямой вызов D0) → вызов слота с flags 1; (3) VTSYM1: каждая точка адреса
таблицы — свой символ `<table>.fnvnx_ap<off>` и своя релокация (требование L1).

Самопроверки (ошибка компиляции): D0 в любой таблице; ссылка на базу таблицы вместо точки адреса; thunk
неизвестного вида.

### Флаги (M6)

`FNVNX_SDD=1` в `tools/link/compile.sh`: `-DFNVNX_SDD=1 -fno-devirtualize -fplugin=fnvnx_sdd.so`. По умолчанию 0 до
единственной полной перекомпиляции. `-DFNVNX_SDD` делает макросы сырых слотов (VSLOT, D26_SLOT, RAWVT, VTM1) тождеством.

### Не закрыто правилом (передано оркестратору)

- `delete[]` полиморфного массива из lifted-кода зовёт слот с флагом 3 (`??_E`); `fnvnx_sdd` знает только бит 0.
  Нужен общий контракт cookie массива MSVC/GCC и ветвь флага 2, либо для таких классов слот остаётся за lifted `??_E`.
- Виртуальные базы: thunk-и с vcall-смещением поддержаны, но construction vtables с pure-virtual и раскладка vbptr
  MSVC — отдельный класс (L1).
- Остаточные дельты vcall (81 место, 21 функция на 65 юнитах): объявление класса в декомпиляции ≠ exe. Список — L1.

### Дополнение: `??_E` (флаг 2)

`<D1>.fnvnx_sdd` теперь `??_E`: флаги 0 → деструктор; 1 → D0; 2/3 → n = слово перед массивом, элементы с последнего,
D1 каждого, при бите 0 `operator delete[]` блока (тот, что находит поиск в области класса; спрашивается у фронтенда
при завершении класса). 12 юнитов: 12 из 12 собираются, ошибок `SDD2:` 0, функций слота 45.
Не сделано: (1) сверка cookie с `cl` (GCC ILP32: одно слово-счётчик перед массивом при выравнивании ≤ 4; для
выравнивания > 4 cookie GCC = выравнивание, у `cl` не измерено); (2) нативное `delete[] p` остаётся циклом GCC
по статическому типу, а не вызовом слота с флагом 3; гейта по всем местам new[]/delete[] ещё нет.
