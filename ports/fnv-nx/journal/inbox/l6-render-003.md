## Решения оркестратора за день

- d3dx9_38.dll — MODULE-LIFT; граница ровно на d3d9.dll.
- Транслятор SM1-3 входит в рантайм (L1: пути компиляции достижимы); заполненный кэш — обязательный артефакт поставки; промах транслируется синхронно в Create*Shader.
- ENV: одна эталонная среда записи (Wine 9.0 + llvmpipe); профили 1280×720 и 1920×1080 с одним режимом; видеопамять 960 МиБ (оценка L5); Ex-интерфейсы реализуются.
- Вместо null-устройства — общий фронт на GL 4.5/llvmpipe.

## Замеры для бюджета (x86-64 хост, не AArch64)

- Транслятор с uam: 2,90 МБ (text 2 717 949).
- Пакет 019: 815 уникальных шейдеров за 116,2 с, 143 мс на шейдер; из них байткод → GLSL 0,16 с на весь пакет, остальное uam. Пик RSS 80 МБ. Выход 3,67 МБ DKSH.

## Где закрывающего правила нет

1. Допустимость 12 пунктов языка SM1-3 (8 без источника, 4 спорных между MS и vkd3d): транслируется надмножество; точное поведение валидатора Windows неизвестно (A8).
2. Выходы класса `pix` (счётчики запросов видимости, чтение целей) между GPU не равны: сверка потока их маскирует.
3. `ProcessVertices` требует программного вершинного конвейера; тела нет (в счёте G-METHOD).
4. Расхождения MS-документации и Wine в умолчаниях (ZENABLE, DEBUGMONITORTOKEN, POINTSIZE_MAX, списки state block): решит воспроизведение записей тестов Wine (утверждения тестов верны на Windows).

## Поправка к заметке 001
