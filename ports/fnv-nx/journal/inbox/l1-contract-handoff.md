## 2. Решения и интерфейсы

**Слова владельца (через оркестратора), действуют:**
- Приоритет один: собрать ELF и отдать L4. «Пока ничего не переписывать, мы даже не загрузились».
- 32 бита / ILP32 остаётся; 39-бит/LP64 отвергнут. Дикий доступ гостя в страницы хоста — записанное допущение.
  MEMSAFE приостановлен.
- Глубокий анализ недостижимости (свежесть аллокатора, A1, сводки записей, сертификаты reach) отложен до первого кадра.
- Wine 9.0 — допустимая реализация: делать ровно то, что Wine 9.0, с одной строкой лога (`fnvnx_wine_fixme(id)`).
- Не принимать решений по именам/тексту/регулярным выражениям в скриптах. Текстовые правила nostub отозваны.
- Экономия окна: ≤ 2 воркеров Sonnet, ≤ 2 тяжёлых процессов.

**Формат гостя (L1 владеет):** ELF32 AArch64 ILP32, PIE, база линка 0, заголовок crt0 «FNXG» (слова +16/+20/+24
пишет `link/ld.py`), `entry(api)` с FnvnxHostApi v3, самоперемещение только RELR/RELATIVE.

**Строгий линк:** множество undefined считается по таблицам символов ELF до линка; weak undefined = красный; без
PROVIDE/--defsym. Архивы всех лидов собираются с `-fPIE` (иначе «read-only segment has dynamic relocations»).

**L3a (владеет подъёмом):** `.text.fnvl`, `L_<addr>`, `I_<key>`, `fnvl_dispatch`; в disp.o `fnvl_disp_table`,
`fnvl_g`, `fnvl_phf_params` (слот занят ⇔ смещение ≠ 0); entries.tsv (kind code|import, последняя строка
`# table_id <sha256 bridge.tsv>`); `fnvnx_lift_enter(eip, esp, teb)`, `fnvnx_lift_imports_init()`,
`fnvnx_guest_invoke`, `fnvnx_guest_current`.

**Ключи импорта (L1 владеет, одна таблица для загрузчика, L3a и GetProcAddress у L5):**
key = 0x00100000 + 16 × индекс среди не-data строк bridge.tsv, сортировка (dll в нижнем регистре, имя).
Адрес возврата-страж 0x000ffff0. Зарезервировано [0x000f0000, 0x00200000). API: `fnvnx_import_key`,
`fnvnx_import_by_key`.

**Загрузчик (L1):** по правилу Windows — SHA-256 exe, заголовки и все секции, строгое связывание импорта, TLS, защита
секций PE (никогда не исполняемо на хосте), блок потока (TEB +0/+4/+8/+0x18/+0x2c). Модули: статические базы для
9 несистемных PE (0x01410000…0x022d0000), 4 статических (d3dx9_38, binkw32, libvorbis, libvorbisfile), перемещения,
экспорт/форвардеры, порядок DllMain, загрузка/выгрузка по требованию. Сигнатуры — `loader/include/fnvnx_start.h`,
`fnvnx_modules.h`.

**Хост (L1 владеет `toolchain/include/fnvnx/hostapi.h`, единственный заголовок; блок TOTALITY TABLE):**
модуль FNVNX_EXT_PLATFORM=11, службы 1–35; 16–33 сокеты и 34–35 — код L5, вносится дословно (`host_sock.inc`,
`sockwire.h`). FNVNX_EXT_NINE 9, FNVNX_EXT_GPU 10 — L6. NO_SERVICE (−254) с 36, BAD_NARGS (−253).

**L5:** bridge.tsv/манифест, платформа Win32; `register_image` → `fnvnx_win32_register_image`.
**L6:** мост рендера (тела d3d9). **L4:** эмулятор и вердикт; получает id ELF, прогон < 1 мин; адрес «главного меню»
и WinMain берёт из своего `tests/s5/milestones.txt`. **L2:** вход N3 для D5 (не сейчас).

## 4. Открытые вопросы и ловушки

- **Служба 10 (ACCESS_FAULT_HANDLER) на консоли не обслуживается:** механизм ядра не доказан. Класс открыт.
- **Сертификаты reach: 0 из 3.** Блокеры: место GetProcAddress в nvapi (нужны факты записи от L5); два места
  CreateFileMappingA (свежесть аллокатора); d3dx9_38 0x56b73e — модуль неизвестен; допущения A1, A3, A4, P.
- `toolchain/guest/tm.cpp`: `_ITM_addUserCommitAction` заведомо неверен.
- Виды FILE_MAP только-чтение/COPY невыразимы (граф таких не показывает). Модуль по требованию с TLS отвергается.
- VM_PROTECT и соседние службы на консоли реализованы по доказательству, на железе не проверены.
- В коде L5 (внесён дословно): цикл ожидания паузы потока не завершится, если поток вышел сразу после запроса.
  Передано L5 через L4.
- В fnv-nx-build висит лишняя ветка `x` (воркер; прокси не дал удалить) — ждёт удаления оркестратором.
- `gate_tests`/`gate_pure` требуют `GATE_OUT=<каталог>` (иначе KeyError).
- Линк тестового PIE: брать мультилиб `-fPIC`.
- Воркеры дважды упирались в лимит аккаунта (сбросы 12:30 и 17:30 UTC); продолжать через SendMessage после сброса.
- Трейлер коммита — ровно тот, что в CLAUDE.md; без строки сессии.
