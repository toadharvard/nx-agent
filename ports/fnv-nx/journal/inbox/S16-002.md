* **did** - Queue items 1 and 3, and the metric definition behind item 2. Branch `claude/fnv-s16` (integration
  merged at start and again at 201165b).
  - `sweep_report.py`: a program is **vacuous only when no parameter set exercised it**. Before, `worst()` ranked
    "vacuous" above "pass". A program that passed six sets and drew nothing under alpha test GREATER 128 therefore
    counted as vacuous. The class is now: over if any set is over, else pass if any set passed, else ill, else
    vacuous. `aggregate` recomputes the class from the per-set columns.
  - **Translator numerics** (the class of the zero-constant rcp/rsq case). The translator gave D3D9's
    implementation-defined results (rcp/rsq/log of 0, nrm of a zero vector) Gallium Nine's clamped values. Those
    match V6n's softpipe oracle. The sweeps compare against the original under WineD3D. Its GLSL (dumped with
    `WINEDEBUG=+d3d_shader`) is plain IEEE: `1.0 / x`, `inversesqrt(abs(x))`, `log2(abs(x))`, and
    `nrm = dot == 0 ? v : v * inversesqrt(dot)`. Its `lit` gives z = 0 for a zero exponent.
    - The default is now WineD3D's, and the game ships the default.
    - Nine stays behind `#ifdef DK_NUMERICS_NINE`, selected with `FNVNX_SHADER_NUMERICS_NINE`
      (`sdp2dksh --numerics nine` / `FNVNX_NUMERICS=nine`).
    - The s6b exec scenes and `render/verify/shaders/{parity,sdpfuzz,vsscenes}.py` keep Nine.
  - **Def overlay for relative reads**. A relative constant read that starts inside a CTAB array went straight to
    the app's constant file. With a0 it can reach a `def`'d register past the array. Example: DISTTREE
    `c[a0 + 10]` with a0 = 1 reads c11 = def (1, -1, 0, 0). WineD3D loads local constants into the constant file
    whenever relative addressing is used. In a shader that defs float constants, these reads now go through the
    existing `dk_relc` overlay.
  - **texkill on SM2+ tests xyzw** (WineD3D, Nine's KILL_IF). We tested xyz, which is the ps_1_x rule. In
    verification: see below.
  - **Conditioning in the sweep**. `sweep_job` never ran the S16 conditioning reference (EPS 1e-5), so no program
    was ever "ill". Now the programs that are over are captured again perturbed, and the reference alone renders
    them. `permreport.py --pref` calls a program ill only when at least 90 % of the candidate's pixels that are off
    by more than 8 lie within one pixel of a pixel the perturbed reference itself moved.
  - **Item 3: the 'unknown' scenes are candidate crashes, and so are the failing draws**.
    - In the 22 published 06f45fbb shards, all 8 'unknown' scenes have `nx_render` rc 1 and no frames. The cause
      is `frame arena full (128 MiB)`: these scenes have 1.4-1.8 M triangles, and every draw is decoded into
      float4 per element in the per-frame arena.
    - Their draws are exactly the failing draws: 355,324 - 346,195 = 9,129 = the sum of these 8 scenes' draws.
    - Fix: d3d9_exec `Reserve()` submits a frame in parts when it does not fit. The pass is reopened with its
      contents loaded, and state ids persist.
    - nxgl's draw index stays frame-wide across the parts, so the per-draw tools and the bisect still index by
      frame.
