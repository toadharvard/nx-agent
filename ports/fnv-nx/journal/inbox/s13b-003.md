* **found** - The ilp32-pointer probe records that fault just above 4 GiB. Of 22 in the published shards, 21 are a
  garbage pointer near the top of the address space plus an offset: invalid input, by design. One is a real port bug
  (be3af13, 3e79aea):
  - **What the exe does:** MSVC adds a base address and a 32-bit index modulo 2^32.
  - **What the port does:** the decomp writes those exe globals as integer constants (`*(char *)(0x011f6370 + i)`).
    With a constant base, GCC's AArch64 ILP32 code at -O1+ forms the address as `add x, base, w, uxtw`, which does
    not wrap. An index of -1 then faults at 2^32 + base - 1, where the exe reads base[-1].
  - **It is wrong code, not only a typing issue:** the same happens for a signed int index and for an explicit
    `(uint32_t)(base + i)`, both well-defined C.
  - **Sites:** in link 0bd144db1464 there are 147 `add x, x, w, uxtw` sites, and only 3 have a constant base:
    - InitFromParams 00a4e0f0 (nitransformdata.cpp, index typed unsigned);
    - FUN_00aa4be0 and SetByteAtOffset 00aa4bf0 (blk_00aa0000_od.cpp, an int index passed as char *, through
      00aa4c10 / 00aa4c40).
* **did**
  - New real-bug cause `ilp32-wrap` (S1): the probe record's address mod 2^32 lands in memory the oracle maps.
  - tests/s13/ilp32_wrap: a synthetic reproducer of the exact native code. check.sh compiles it with the given ILP32
    compiler and reports per form; it skips without one. Ubuntu GCC 13.3:
    - -fwrapv-pointer has no effect;
    - -fno-tree-ter fixes the int, unsigned and uint32 forms but not the char * form;
    - a symbol base (extern array, PIE or not) and an asm-hidden base are correct.
* **for S1** - Fix the 3 functions in the prepared source. Reach the table through its `__fnv_<addr>` global symbol,
  as other exe globals are, or hide the constant base, and type the index as the exe uses it. A global flag is not
  needed: the 144 register-base sites only matter if code relies on a wrapping offset, and no record shows one.
* **for the toolchain owner** - Run tests/s13/ilp32_wrap/check.sh with FNVNX_A64_CC set to the fnvnx-a64 gcc (GCC
  15.2). by_cast32 is a reportable GCC wrong-code case: -mabi=ilp32 is deprecated upstream, so a local patch or the
  source workaround is the realistic fix.
