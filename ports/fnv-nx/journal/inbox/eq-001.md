* **proposals (rules owner)**
  - PERM1: 5 units compile on the target only through -fpermissive. DECL1's SDK prototype returns a pointer the
    decomp stores in an integer (CreateMutexA, FindWindowA, FindFirstFileA), takes HKEY / HHOOK where the decomp
    passes void *, or strrchr returns const char * where the decomp assigns it to char *. A rule that writes those
    conversions out as casts (driven by GCC's -fpermissive diagnostics, one table per site) would let MSVC compile
    them and would remove the target's dependence on -fpermissive. It touches sites tree-wide, so it needs a census
    run, not a one-stream edit.
  - ANON2 under MSVC: `alignas(T) unsigned char m[sizeof(T)]` has an exact MSVC 2008 meaning,
    `union { unsigned char m[sizeof(T)]; T fnvnx_raw_m; }` (MSVC took T in an anonymous union). That needs a
    macro, `FNVNX_RAW_STORAGE(m, T...)`, in ANON2's output, which later rules (TAIL1, the DECOR patterns) would
    have to read: 2 units.
* **decided**
  - CTOR1's PLACEMENT-NULLCHECK (61 functions) is a compiler-model class. MSVC 2008 null-checks every
    new-expression, even for an allocation function without throw() (measured with a tagged placement form at /O2
    and /Od). GCC -O2 emits no check, so the target code equals the explicit call's. Tried and reverted (no
    reduction).
  - EXTERN-RELOAD (STATIC1, 25): image-bound variables must have external linkage for the link-by-address. The
    reload after a call is the optimizer losing the internal-linkage assumption; the values are the same. Declared.
  - the std::abs code differences (3 locally): the exe's std::abs(float) at 0x00408840 is MSVC's out-of-line
    `(float)fabs((double)x)` (0x00408860 -> CRT fabs). The target inlines the standard abs: the same value for
    every input. CRT-INLINE.
