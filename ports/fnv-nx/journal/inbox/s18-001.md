* **did: the scenario bench** (tools/scenario/README.md; 01c22ab, 48a5971)
  - Five scripted scenarios (tools/scenario/scenarios.json): `boot-menu`; `newgame` (main menu -> New -> the intro
    cell, the creation menus, then Goodsprings); `cells` (coc into GSDocMitchellHouse, GSProspectorSaloonInterior,
    Goodsprings, QuarryJunction); `saveload` (save A, load A, save B); `quest` (the first six stages of the
    Goodsprings opening quest, found by its title in FalloutNV.esm, so no editor id is guessed).
  - One input model on both sides: keys only (xdotool keysyms -> HID usages), console lines typed key by key.
    `scenario.py compile` expands the macros to press / wait / until (milestone | file) / mark.
  - Guest: `tools/scenario/emu_scenario.py` wraps tests/s5/emu_guest.py. Key events go through the host API's
    input_poll on the emulator's virtual clock, so a run repeats exactly. Milestone gates use emu_guest's table,
    and the run ends with "scenario complete". The summary gets the steps, marks, gate timeouts, [fnvnx] lines and
    instructions per frame. The scenario's files (s18_* saves, the scof log) are kept before farm_boot.sh deletes
    its SD root.
  - Original: `tools/scenario/wine_scenario.sh`. It uses the sweep's prefix and ref_ini.py inis, xdotool, and
    fnvtrace when tools/lockstep is present. Milestone gates become fixed waits (`wine_s`); file gates are polled.
  - `savediff.py`: the round trip. Header and screenshot are left out (the screenshot size is calibrated per pair).
    Content-defined chunks are aligned, and each region is keyed by its anchor, so the original's own round-trip
    differences can be subtracted.
  - `scenario.py report`: one fnvnx-scenario/1 per scenario, one entry {measured, count} per D25 target (the
    scenario.py docstring says what each counts). The md copy has counts and scalars only; game text stays in the
    private json. `metric`: the targets measured and the sum of counts.
  - `tools/farm/scenario_job.sh`, runner job `scenario`:
    - per scenario: compile and validate against the ESM, guest, Wine, then S5-boot's lockstep compare, R4's
      threads lane, NX1's run.py and the report;
    - the original's runs are cached under a key (exe, Data listing, plan, trace list, harness, Wine);
    - private results go to `scenario/<link12>`, and a metric sidecar is written.
  - T1's quick_job: check `scenario` on lane A after frames (QUICK_SCENARIOS default "boot-menu saveload", on
    full_job's build directory). quick_plan class `scenario`.
