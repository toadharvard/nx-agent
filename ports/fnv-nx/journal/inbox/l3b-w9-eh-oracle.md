# l3b-w9: EH / SEH conformance oracle (path plan 4.5, second half; status item 4g)

Code: `ports/fnv-nx/lift/proof/ehoracle.py`, a pure function of the image bytes and Wine 9.0's rules; it imports nothing of rt/, the lifter or tools/ehtables.py (only pefile). Rules are transcriptions of Wine 9.0 `dlls/msvcrt/except_i386.c` and `cppexcept.h` (file:line in every docstring and comment):
- `cxx_frame_handler` 555-649 (magic check 562, SYNCHRONOUS/C-exception skip 566-569, unwinding pass 570-574, no tryblocks 576-580);
- `call_catch_block` 374-447 (tryblock window 395-396, catch(...) only for a C exception 418-420, first match, `cxx_local_unwind(frame, descr, start_level)` 429, new trylevel end_level + 1 at 430, continue_after_catch 445);
- `find_caught_type` 248-268 (pointer, else strcmp of `type_info.mangled`, CONST/VOLATILE flag rules);
- `cxx_local_unwind` 305-326 (invalid level -> terminate());
- `_except_handler3` 863-928 and `_except_handler4_common` 932-990 (the FIXME "no cookie validation yet" is at 946), `msvcrt_local_unwind2/4` 768-817 (TRYLEVEL_END -1, V4 -2; level with no filter runs its handler), SCOPETABLE_V4 header layout 134-141, structure layouts 46-96, cppexcept.h 60-117.

Decision function: FuncInfo -> table {(state, kind): row}. State = every trylevel the frame can have (-1 .. the largest level any table names). Kind = a C exception, or each of the 11 ThrowInfos of the image set. Row = (catch block i, j, handler, unwind sequence to the tryblock's start level, trylevel after) or ContinueSearch; plus the unwinding-pass sequence per state. SEH: per scope level, the hunt chain (level, filter, handler) and the cleanup sequence.

Inputs: exe and the 7 images' bytes (gamedata/exe, gamedata/redist of fnv-nx-build, private, not in this repo), relocated to the assigned bases (derived from each image's text start in the facts); the lifter's side is the facts of l3a-lift/facts (`ehtables.json` per image, what lift/gates/gate_eh.py reads). The oracle's FuncInfo universe is BY RULE (v2): the eax operand of every decoded `mov eax, imm32 ; jmp T` whose T reaches a frame handler, resolved on decoded code: (R-a) `jmp [slot]` / a body that calls or jumps through an IAT slot whose import name is __CxxFrameHandler/3/4; (R-b) a static CRT copy: the entry eax is stored to a local before eax changes and that local is pushed before the first call (the `descr` argument of Wine's internal handler, except_i386.c:656-672). The magic scan stays as a cross-check only (ASM-222): every hit outside the universe is reported as `magic_not_funcinfo` with a proof (the image has no frame-handler import and no static copy, or no thunk names it); a hit that a thunk names but whose jump is no frame handler is a finding. ThrowInfo and scope-table ADDRESSES and the scope table lengths are taken from the facts (code-flow facts, R1/R3/R4: not derivable from bytes alone); their contents are parsed from the bytes.

## Result v2 (global, all 8 images, facts l3a-lift/facts at fnv-nx-build fd59184, oracle at the commit of this note)
- FuncInfo universe by rule: 11,972 decoded `mov eax, imm; jmp` thunk sites in the universe spans (exe 10,082; d3dx9_31 1,340; d3dx9_38 1,613; the 5 C-only modules 51 in total, 0 reaching a frame handler) of which 4,643 reach a frame handler: exe 4,346 (all by R-b, static copy), d3dx9_31 157 (import), d3dx9_38 140 (import call). The set of eax operands equals the facts' FuncInfo set exactly (4,346 / 157 / 140); `magic_not_funcinfo` = 5 (atimgpud, binkw32, gdffalloutnv, libvorbis, libvorbisfile: no frame-handler import, no static copy, unwind_count = tryblock_count = 0), each with its proof in the report.
- tables compared: 4,643 FuncInfo, 218 SEH scope tables (exe 75 = 73 V4 + 2 V3, 30, 9, 3, 7, 20, 36, 38), 11 ThrowInfo; states 18,325, type (catch-block) entries 260, exception kinds 12 (C + 11 ThrowInfos), decision rows 235,261, fields compared 43,210; agreement 235,261 of 235,261.
- throw sites (change 2): every call (or tail jump) of a thrower is resolved on decoded code; a thrower is a function that stores 0xe06d7363 into a record or copies a record template whose first dword is it (the exe's _CxxThrowException at 0xec7894 uses the template at 0x10f1f80; the frame handlers that only COMPARE the code are not throwers), or an IAT slot named _CxxThrowException, or a stub whose whole body is `jmp` to either. The ThrowInfo is the 2nd stack argument: a constant push, or a register set by a constant; at a block boundary every path into the block (fall-through and each decoded direct branch) must give a constant. ## What the oracle does not cover (stated, not claimed)
- catch continuations (`conts`, code flow), frame-handler registrations (R3, code flow), the filter functions' own results (code), copy_exception/destructors (data movement, not dispatch), the V4 cookie (Wine does not check it; the header is recorded).
- the scope table length is a fact of the code (R4) taken from the facts; the oracle checks the entries it covers (prev chain valid, filter/handler in .text), not that no further entry exists.
- the oracle compares the lifter's TABLES with the bytes under Wine's rules; it does not run rt/msvcrt_eh.cc (the runtime's use of the tables is the boot machine test of w3/w9 CONTEXT spec).
The report JSON holds table addresses derived from the exe and is not committed (private); rerun: `python3 -I lift/proof/ehoracle.py --facts F --game G --redist R --wine WINE_TREE --out ehoracle.json` (the report goes into the facts directory, private, where gate_eh reads it), exit 0 iff no finding.
