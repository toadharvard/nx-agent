# J-XXXX L6 RENDER: правила потока и вердикт по несмёрженным веткам (2026-11-10)

Поток: `l6-render`, ветка `claude/fnv-l6-render`. Числа переписи тотальности — в `l6-render-002.md`.

## Правила (R11, уточнение по коду)

| # | Правило | Что закрывает | Допущение |
|---|---|---|---|
| RD1 SPEC | Одна таблица интерфейсов D3D9 (каждый метод, каждый параметр: направление и вид). Из неё порождаются: каркас COM-классов гостя, сериализатор потока, прокси-регистратор для оригинала под Wine, сравнитель. Метод без тела или без записи — ошибка сборки | «unjournaled» d9cap (7 классов), заглушки null-устройства | A8: контракт D3D9 задан документацией |
| RD2 ENUM | Аргументы-перечисления типизированы; `switch` без `default`, `-Werror=switch-enum`. Значение вне перечисления обрабатывается одной функцией области (контракт D3D9: вызов отклонён либо значение хранится без действия), а не `default` по месту | `NX_PLAT_UNSUPPORTED`, `Skip()` | A8 |
| RD3 ORDER | Устройство кодирует команды бэкенда в порядке вызовов D3D9. Буферы конечны: при заполнении — отправка и продолжение. Путей «отбросить draw» нет | `Frame` (сортировка пакетов, `droppedDraws`, `kMaxPackets`, `kMaxPasses`, `StateCache` «0 when full») под D3D9-устройством не используется | — |
| RD4 SHADER | Транслятор тотален по (модель, команда, регистр, модификатор, usage, адресация) SM1-3: вселенная порождается из таблицы команд; строка не `ok` — ошибка сборки. Трансляция только вне консоли | sweep по шейдерам игры как приём | A2' (uam корректен) |
| RD5 FFP | Фиксированный конвейер — одна пара программ (VS, PS), состояние (TSS, свет, материал, texgen, туман, FVF) передаётся данными. Специализация допустима только хэш-равной | FFP-состояния «recorded, unused» | — |
| RD6 ENV | Ответы среды (caps, режимы адаптера, идентификатор, память, Ex) — одна фиксированная таблица; регистратор подставляет её оригиналу, гость отвечает ею же. Тогда поток гостя и оригинала сравним вызов в вызов | расхождение потока из-за ответов Wine | таблицу утверждает владелец (ENV-TRUTH) |
| RD7 LOCK | Память Lock у обеих сторон — функция потока: регистратор отдаёт игре свою теневую память (DISCARD → нули, иначе прежнее содержимое) и копирует при Unlock; гость делает то же | неинициализированные байты в записях VBU/TEXU | — |
| RD8 BACKEND | Фронт и транслятор общие для deko3d и GL 4.5 (llvmpipe, host module 10); различие только в слое бэкенда, проверяется N0-сценами на обоих. Null-устройство удаляется (указание оркестратора 2026-11-10) | null-устройство в гейтах | — |

## Несмёрженные ветки (сравнение с `claude/port-nsw-un6t9s`, только пути рендера)

| Ветка | Что есть только в ней | Вердикт |
|---|---|---|
| `port-nsw-render` | таблица состояний D3D9 по умолчанию (`d3d9_state.c` +63, `test_d3d9_state_table.py` 246 строк) | перенести после гейта RD2 |
| `port-nsw-render` | S6b «def-константы при привязке» (`s6b_relc.c`, WIP, не проверено) | отложено: проверить гейтом RD4 |
| `port-nsw-render` | `n1/engine_stubs.cpp`, `renderer.cpp`, `selftest.cpp` (+630 строк) | не переносится: замена кода игры выше границы D3D9 |
| `fnv-render-veg` | `veg_dk.glsl`, `grass_dk.frag.glsl`, `grass.vert.glsl` | не переносится: рукописное семейство без хэш-равенства |
| `fnv-g1-gpu` | статические варианты эпилога (WIP) | отложено до L7: допустимо только как хэш-равная специализация |
| `fnv-render-land`, `fnv-render-lit`, `fnv-s5-menu` | в путях рендера отстают от интеграционной ветки; своего нет | нечего переносить |
| `fnv-s16` | 0 отличий в путях рендера | уже в интеграционной ветке |

Итого: переносится 1, отложено 2, отклонено 2 группы.

## Что не соответствует правилу в интеграционной ветке (вход, не вердикт)

- `render/native/n1/*` и `overrides.tsv` (29 строк адресов, 569 заменённых функций гостя): выше границы D3D9.
- `render/native/shaders/*` (30 рукописных шейдеров семейств): допустимы только как хэш-равные специализации.
- `toolchain/game/null_d3d9.cpp` (3 332 строки): удаляется после первого кадра через RD1.
- `front/dynres.h`: динамическое разрешение отменено решением владельца.
