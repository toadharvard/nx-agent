* **the mirror case, and why the fix is per declaration.** Hand-stored image vptrs (hand_vptrs 'image') are
  exe-ordered objects.
  - Declared hierarchies with a virtual destructor reach some of them: the shader-creator map under
    `NiTStringTemplateMap::SetAt` ran an output function as IsKeysEqual.
  - Table option `image-vptr-minus-one [RTTI regex]`: minus-one copies (D1/D0 thunks, then exe slot k at k+1).
    - All 785 referenced vftables: **1 -> 3,461 skips** (TMapStandIn and the other call-only stand-ins dispatch
      the same objects in exe order).
    - The NiT* containers only (133): 1, past the registration.
  - So the same objects are dispatched in both orders. Proposed program-wide decision (completing D22): one order,
    minus-one, everywhere:
    - (a) D22 for paired classes (S1);
    - (b) `virtual ~X()` for the slot-0 placeholder of every call-only declaration (S1-refs; callonly_vt.py's list);
    - (c) a minus-one native vtable for every hand-stored image vftable (S1 hand_vptrs / S2c).
    They must land together: each alone moves the boot backwards, as measured.
