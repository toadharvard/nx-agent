# The compiler as two recipe steps (COMPILER-STAGE)

The game's compiler (GCC 13.3.0 + `msvcmodel.patch`, with the guest runtime built by it) is built by two `run` steps of the product root `toolchain`
(`ports/fnv-nx/toolchain/build.json`), each in the sandbox with mounted inputs only. The key of a step is the content of what the sandbox mounts for it
(sources, patches, records, the host tools of the declared debs, the step's own script and, for stage 2, stage 1's output tree). Nothing is keyed or listed in a
script: the scripts have no stamp, no hash constants and no list of their inputs. Every path a script touches is a constant at its top; a change of the sandbox's
mount points changes those lines only.

| | step `gcc1` (`stage1.sh`) | step `rt` (`rt.sh`) |
|---|---|---|
| what | GCC + msvcmodel.patch, binutils of the deb copied in as `aarch64-none-elf-*` | plugins' flags, newlib, libgcc, libstdc++/libsupc++, MANIFEST.json |
| output | `STAGE1` = `prefix/` + `b-gcc/` + `src/` | `COMPILER` = the install prefix: bin/, lib/, plugin headers, runtime libraries, crt, MANIFEST.json |
| mounts | `/ext/gcc/gcc-13.3.0.tar.xz` (external, sha256-pinned GNU tarball); `/in/repo/toolchain/msvcmodel/msvcmodel.patch`; `/in/records.sh` | `/in/1` = STAGE1; `/in/repo/toolchain/gcc/{x19-x27.patch,libstdcxx-nosized.patch,newlib-guest.patch,cfg_link.py}`, `/in/repo/link/guest.ld`, `/in/repo/toolchain/dispatch/fnvnx_dispatch.cc`, `/in/repo/toolchain/msvcmodel/msvcmodel.patch`; `/in/records.sh`; `/in/plugins/<name>.so` (every plugin of the records' PLUGIN_ORDER); `/ext/gcc/gcc-13.3.0.tar.xz`; `/ext/newlib/newlib-4.6.0.20260123.tar.gz`; `/ext/autotools/{autoconf-2.69.tar.xz,automake-1.15.1.tar.xz}`; `/ext/buildscripts` (devkitPro/buildscripts at 5740da9beb433ff9f5b724fafc1127f3a5ddc944) |
| debs | `/deb/<name>/...`: the host compiler (g++-13-x86-64-linux-gnu), make, python3, mawk, tar, coreutils, binutils-aarch64-linux-gnu, libgmp-dev, libmpfr-dev, libmpc-dev, zlib1g-dev, libc6-dev, base-files, and the shell and text tools below | the same plus perl, m4 (the autotools the newlib regeneration builds) |
| scratch | `/scratch` (writable, the same absolute path on every run): `w/` (work) and `prefix/` | the same `/scratch/w`, `/scratch/prefix` (stage 1's trees are copied back to them) |

- `records.sh` is generated by `records.py` (a generator of the root) from `verify/targets.json`, `guest_compiler.json` and the recipe's declarations
  (`runtime_configure`, `runtime_configure_patch`, `runtime_cflags`, `semantics_set`, `PLUGIN_SOURCES` order, `plugin_args("native")`). The scripts read nothing of
  the repo's python.
- The plugins `/in/plugins/*.so` are the recipe's own `plugin:<name>` stages, built against stage 1's `-print-file-name=plugin` headers (`STAGE1/prefix`).
- Absolute paths: GCC's build tree (libgcc is configured and built inside it) and the compiler's configured paths are absolute, so stage 2 copies `STAGE1`
  back to `/scratch/prefix`, `/scratch/w/b-gcc`, `/scratch/w/gcc-13.3.0`, the paths stage 1 built at. The scratch path is the sandbox's constant.
- Host tools: the scripts add every `/deb/*/usr/bin`, `/deb/*/bin` to PATH and every `/deb/*/usr/lib/x86_64-linux-gnu` to LD_LIBRARY_PATH by pattern.
- No network: GCC's tarball, newlib's, autoconf's, automake's and devkitPro/buildscripts are externals (fnv-nx-build mirrors by commit and tree_sha256).
- Not in the tree any more: `build_key`, `stage_keys`, `toolchain_tree_*` of the old MANIFEST (the key is the stage key of the step), the git-based toolchain tree hash.

## Debs the steps need that env.json (`debs.packages`) does not pin yet (L1's file; checked 2026-11-15)
`bash` (the scripts use arrays and process substitution), `sed`, `grep`, `patch`, `xz-utils`, `findutils`, `diffutils`, `gzip`. (`mawk`, `tar`, `make`, `coreutils`,
`python3`, `perl`, `m4` and the cross/host compilers are pinned.)

## Check done here (no sandbox yet)
`bash -n` on both scripts; the stage-2 `tlflags` function gives byte-equal output to `recipe.semantics_for` on the cand2 compiler (c and cxx).


## Roots (build.json) and externals
- `toolchain-stage1` (step `gcc1`, output `STAGE1`) and `toolchain` (build.json at its top) (compiler = stage external `{root toolchain/stage1, output STAGE1, at /ext/stage1}`, the eight `plugins` in load order,
  step `rt`, output `COMPILER`). Mounts are exactly the constants at the top of `stage1.sh` / `rt.sh`; `records.py stage1|stage2` are the generators (input: the verify directory, mounted at `/in/ports/fnv-nx/verify`).
- Externals (fnv-nx-build, orphan mirror branches): gcc `tools/gcc-src-13.3.0` f445876d (tree f50e0b05...), newlib `tools/newlib-4.6.0.20260123` 2fb73524 (af2b544d...), autotools `tools/autotools-src` 2dee1098 (6dbd091d...),
  buildscripts `tools/devkitpro-buildscripts-5740da9b` f34068c8 (f0923ebe...); full hashes in the two build.json files.
- Debs: the lists name `bash sed grep patch xz-utils findutils diffutils gzip` which env.json does not pin yet (all others are pinned); the roots are not admitted until they are.
